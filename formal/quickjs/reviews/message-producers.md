# Incoming message producers

This source review did not establish a reachable outside sender under the current application launch and endpoint-creation contracts. Delivered references are not independently filtered, so the confinement argument depends on establishing that the communication peers remain confined.

- Application startup requires a top-level window without an opener and an active service-worker controller ([`start`](../../../src/guest/window.ts)). Controlled application documents receive COOP `same-origin` and CSP `frame-ancestors 'self'` and `frame-src about:` ([`headers` and the navigation response](../../../src/runtime/worker.ts)). The host's [Open link](../../../src/manager/components/application-list.tsx) uses `noopener noreferrer`. The manager's [runtime connection iframe](../../../src/manager/services/runtime-bridge.ts) hosts the trusted management bridge, rather than an application document.
- [`createGuestWindowContexts`](../../../src/guest/contexts/window-contexts.ts) prepares application frames and popups. Its `postMessage` checks known or prepared application windows, clones the payload and privately marks the synthetic delivery. `BrowserEnvironment.get` restricts an unknown native Window to its `closed` property ([window access checks](../../../src/guest/browser.ts)).
- [`createGuestWorkers`](../../../src/guest/contexts/worker-factory.ts) uses host-prepared Blob bootstraps and sends initialization before returning the worker. Shared-worker names include application, generation and entry identity. [`startDedicatedWorker` and `startSharedWorker`](../../../src/guest/contexts/worker-bootstrap.ts) prepare the guest before replaying queued messages or exposing a connection. This relies on the creator/peer endpoints remaining confined and bootstrap URLs and management ports remaining private.

[`GuestEngine.owner`](../../../src/guest/engine.ts) defaults an otherwise unclassified native object to the browser host. `BrowserEnvironment.get` and `invoke` still contain generic native property/call forwarding, including native MessagePort sends and stream writer operations. If a native MessagePort or WritableStream arrived from an outside peer, these operations could send data to that peer. Writing private data through such a handoff would be application-controlled communication to that peer, distinct from the separately trusted browser services.

The selected [EventPolicy](../../../src/guest/event-policy.ts) functions `listener` and `admitEvent` check the receiving target, callback lifetime and native event type; they do not authenticate the sender. MessageEvent `data`, `source` and `ports` use delegated results. `BrowserEnvironment.set` also installs raw `onmessage` handlers, so admission through its EventTarget listener wrapper would not cover every delivery path.

C3 must establish closed peer creation and transfer provenance across these paths. If later work exposes outside messaging, reference admission must cover listeners, handler attributes and transferred endpoints while preserving guest-created events and trusted synthetic replays. The native `isTrusted` flag alone cannot express those producer relationships. This inventory is a verification premise, not a demonstrated escape or a requirement to reject currently permitted confined-peer communication.
