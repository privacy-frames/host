# Confinement models

These are bounded design models, not a proof of the browser or TypeScript. The
boolean fault switches state explicit assumptions about mediation and authority.
A passing safe check cannot prove that the actual implementation satisfies them.

- `Confinement.tla` is the first two-context sketch.
- `Lifecycle.tla` adds parent ownership, pending host/application messages, one
  installation generation replacement and fault controls for stale and forged authorization.
  `Publish` means granting usable execution authority. It does not mean returning
  any handle: the implementation may return a mediated Worker before its guard is
  ready, provided application code and unsafe effects cannot start prematurely.
  The model currently treats replacement as an atomic revocation of all modeled
  contexts. This is not service-worker controller replacement, which retains
  persisted bindings. Actual child closure, native termination and residual
  handles need a separate correspondence argument.
- `Registry.tla` abstracts one actual ContextRegistry identity and two owner
  names. The separate trace test compares real method sequences against a graph
  generated by TLC. It compares 10,000 length-four sequential operation sequences
  using in-memory storage, including direct and bearer resource capabilities.
  The three live persisted phase labels project to one bound state; revalidation
  checks authority without writing those labels. It does not verify bearer secrecy,
  browser guards, persistence, actual client identity or concurrency. A wrong-owner mutation must be rejected by the comparison.
- `RegistryRace.tla` retains the former non-atomic CacheStorage schedule as a
  countermodel: two independent registries check an empty client before either
  writes, and both bindings succeed. The current IndexedDB store enforces client
  and context uniqueness inside a transaction. Its native tests and remaining
  proof obligations are described in the
  [implementation mapping](../implementation-mapping.md#atomic-context-bindings-across-controllers).
  This countermodel does not describe the new store's transaction semantics.
- `GenerationRead.tla` separates the transaction snapshot, generation check and
  later delivery across an installation replacement. See
  [generation-reads.md](generation-reads.md) for the bounds, fault controls and
  corresponding browser IndexedDB observations.
- `Admission.tla` models two resources, trusted verification and commit, requests,
  a private-data bit that survives closing and reinstalling, and fault controls.
  It assumes verification is correct, admitted resources cannot change, and the
  installer cannot read runtime private state. It does not model actual digests,
  installer network requests, browser caches or cross-origin rules.

The safe configurations check all stated model invariants. Fault configurations
must yield their named counterexamples. Reachability controls deliberately assert
false properties to establish that child execution, generation replacement and
private storage are reachable. The saved `traces.json` contains TLC output and
input hashes; it is not an implementation trace.

To reproduce the checks, install Docker and fetch the pinned TLA+ tool jar:

```sh
mkdir -p .tools
curl -fsSL https://github.com/tlaplus/tlaplus/releases/download/v1.8.0/tla2tools.jar -o .tools/tla2tools.jar
formal/confinement/check.sh
python3 formal/confinement/check-generation-reads.py
python3 formal/confinement/capture.py
node formal/confinement/registry-trace-test.ts
node --test formal/confinement/registry-concurrency-test.ts
node test/controller-context-storage.ts
```

The scripts check the jar hash and use a pinned Java image without network access.
The pinned jar SHA-256 is
`011267fca25d0752cf18894dd585cd28b96960c112ea8a20b823ea770e7e10cd`.
The upstream v1.8.0 asset changed on October 30, 2026; the checks and saved
model traces were rerun against this published digest. A later replacement will
fail the hash check until reviewed.
The separate [formal workflow](../../.github/workflows/formal.yml) runs the
model checks, registry comparison and its wrong-owner fault control on pushes
and pull requests. Its browser jobs also run selected receiver, startup and
implementation-comparison fixtures; they do not cover every documented route.
The lifecycle safe run explores 114 distinct states; the admission safe run
explores 47. The registry run explores 8 states. These are separate models; their invariants have not been composed into a proof of the whole runtime. These finite
checks do not establish completeness of modeled browser actions.
