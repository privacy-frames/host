# Boa browser/Wasm feasibility

Research date: 2026-11-18 UTC. Evidence branch: `research/wasm-study-boa`.

Boa v0.22 can run a persistent guest context in browser Wasm and synchronously call back into guest functions during native DOM event dispatch. The retained probe demonstrates nested dispatch and `preventDefault()` before both native dispatch calls return, in Chromium and Firefox. This requires explicit context handoff around each native call and the engine's function-call API. A plain persistent `RefCell` rejects reentry; evaluating callback source with nested `Context::eval` also fails the exception-continuation control.

This establishes an embedding mechanism, with substantial browser-binding work still required. The unchanged generated webidl2js fixture fails in both browsers, including with Intl enabled. The original Pitch bundle parses but stops at its first missing `document` access. Neither result establishes application support. Application Wasm, application service workers and IFC remain excluded.

## Synchronous native event reentry

The persistent owner is a thread-local `RefCell<Option<Context>>`. Each native function receives the currently executing `&mut Context` from Boa. Before crossing into browser JavaScript, it lends that reference to a scoped mutable TLS slot. The browser listener enters a Wasm export that uses this scoped reference rather than borrowing the persistent owner again. That export resolves a rooted guest function and calls `JsObject::call`; a further guest-to-browser call explicitly lends the shorter mutable reference into another nested scope. Ordinary native-origin events use the idle persistent owner.

This follows scoped-tls-hkt's documented mutable-key contract: `with` makes the slot appear unset for the entire callback, and overlapping mutable access panics. `set` restores the previous slot when its synchronous scope ends. The embedding contains no unsafe block, raw context pointer, unchecked borrow or leaked mutable reference. Its reasoning depends on that library contract and on all context-using native call paths following the same handoff discipline; this is not an independent audit of the TLS library or the engine's internals. An asynchronous browser callback cannot retain the scoped reference. A callback arriving later must enter the idle owner. [ScopedKeyMut documentation/source](https://docs.rs/scoped-tls-hkt/0.1.5/src/scoped_tls_hkt/lib.rs.html#549-636), [Boa call implementation](https://github.com/boa-dev/boa/blob/337a3668a0dc86dd401ea20906e782249a64a228/core/engine/src/object/operations.rs#L429-L465), [native function contract](https://github.com/boa-dev/boa/blob/337a3668a0dc86dd401ea20906e782249a64a228/core/engine/src/native_function/mod.rs).

Executed path: guest script → native Rust `host` → imported browser function → real `button.dispatchEvent(cancelableEvent)` → browser listener → exported Wasm callback → guest function → nested dispatch → guest function → native `Event.preventDefault()`. Both native `dispatchEvent` results are false and both events have `defaultPrevented === true`. The guest trace is `outer-start,inner,outer-end`. A separate idle native dispatch also cancels correctly and nests. These are real browser Event/Node objects, with hand-written fixture adapters rather than general DOM interfaces.

The naive control deliberately omits the scoped handoff. Its callback reports `Context already borrowed`, dispatch returns true and cancellation does not occur. This demonstrates why registering a callback around the persistent `RefCell` alone is insufficient.

Thrown guest listener errors are caught by the fixture listener adapter and recorded while native dispatch completes normally; browser-level uncaught exception reporting is not implemented. Native host errors become catchable guest errors, and subsequent evaluations retain the existing guest state. An alternate callback-source evaluator demonstrates a further boundary: nested `Context::eval` can return a guest exception yet corrupt the outer continuation's expected call state, producing `TypeError: not a callable function`. The retained [Chromium](boa-probe/receipts/chromium-nested-eval-control.json) and [Firefox](boa-probe/receipts/firefox-nested-eval-control.json) controls reproduce this failure. The supported fixture uses `JsObject::call` for callbacks. This is an observed failing embedding pattern, not an upstream root-cause diagnosis. [Script evaluation source](https://github.com/boa-dev/boa/blob/337a3668a0dc86dd401ea20906e782249a64a228/core/engine/src/script.rs#L176-L183).

## Identity, prototypes and reusable bindings

A guest Map caches one wrapper per admitted native handle. Repeated access preserves `===`, an expando and an added guest prototype method. This proves a small mapping can preserve those properties, not that Boa provides browser wrappers or weak lifetime management. The fixture roots the context and guest callback object for the page's lifetime. Listener removal, detached nodes, cross-heap cycles, finalization and long-running memory retention remain unqualified.

The unchanged webidl2js 21.2 generated fixture executes in a fresh Boa context with four fixed native-operation adapters. It fails during `StudyNode.appendChild` conversion with `TypeError: not a callable function`, traced through `implForWrapperWithInterface`. The same generated code passes in the companion QuickJS study. Boa's basic private-field stamping and private-brand/optional-chain/lazy-getter controls pass, so those isolated features do not identify the cause. The failure occurs before the fixture completes its branding, argument checks, identity and native-property assertions. No generated source was patched or downleveled to make it pass. The exact source, trace and dependency locks are needed for further diagnosis; the failed fixture prevents recommending this generator/Boa composition as qualified reuse.

## Original application and Intl

The original Pitch main bundle is 287,996 bytes, SHA-256 `5bf9a6fd27798274c5a5c03473a66ee96ecc6bfe8bd4c04c78ac1c93d55ca5ff`. A fresh bounded context parses it unchanged and begins execution, then throws `ReferenceError: document is not defined` at the first unavailable DOM access. Both browsers and both feature builds produce that result. The fixture sets the engine loop-iteration limit to 1,000,000; this is not a wall-clock, parser or heap bound. There is no application patch, mock document or native execution of application source.

The base build has no Intl. The additional `intl_bundled` build successfully runs `new Intl.DateTimeFormat('en-US', { dateStyle: 'long', timeStyle: 'short', timeZone: 'UTC' }).format(new Date(0))`, returning January 1, 1970 at 12:00 AM, with U+202F before AM. This matters because Pitch constructs this formatter. Enabling engine Intl is feasible without modifying app source, but it does not address the missing DOM or other application APIs. The base and Intl Wasm binaries are 5,971,064 and 20,836,055 bytes respectively, uncompressed, before wasm-opt or deployment compression. Exact bytes and hashes are in the receipts.

One local startup sample per browser/build measures fetch/compile/instantiate and context initialization. These are warm-machine fixture measurements, not app performance or a cold-start distribution. Pitch evaluation reaches its missing API in about 150 ms in the measured Chromium runs; no rendering or workflow completes.

## Authority boundary and implementation implications

The fixture exposes only fixed operations and string results. The admitted-resource operation returns one in-memory resource and rejects an external URL; counters record one allowed and one denied request. Guest `window`, `document`, `fetch` and `Worker` are absent, and guest `Function('return typeof window')()` remains inside Boa. Browser request receipts contain fixture resources only. These controls establish the fixture's limited surface. They do not prove that a general DOM bridge prevents script insertion, event-handler source compilation, navigation, inherited native constructors or access through returned objects.

The reusable pieces demonstrated here are the engine, its module/job mechanisms, wasm-bindgen's imported/exported calls, a scoped context handoff and native browser rendering/buffer/storage operations. Persistent ownership, guest/native identity maps and the fixed adapters are newly written fixture code. A complete Web API binding inventory, lifetime coordination, application resource policy, deadlines and browser conformance remain implementation work. The generated-binding incompatibility needs diagnosis before that reuse path can be accepted for Boa. The next Boa integration task is to reduce the generated fixture failure without changing the application or generator output.
