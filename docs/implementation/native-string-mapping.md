# Native string mapping

CSS declarations, stylesheet text and `Audio` sources now pass through private string-conversion wrappers. Native Web IDL decides when to consume each argument; the wrapper converts the original input once, maps that primitive, and returns a string. Property names, priorities, indices, missing arguments and optional `undefined` arguments retain their native conversion order and defaults.

`setProperty` values and supported CSS property setters treat `null` as empty, as their `LegacyNullToEmptyString` declarations require. `cssText` does not. `replace` and `replaceSync` use explicit `USVString` conversion. Other CSS-bearing arguments use deferred DOMString conversion; the native operation retains its own further conversion.

The earlier `CSS.escape` mode probe was removed. Actual browser bindings differ between APIs: [Gecko's escape operation](https://raw.githubusercontent.com/mozilla/gecko-dev/master/dom/webidl/CSS.webidl) uses DOMString while its [FontFace inputs](https://raw.githubusercontent.com/mozilla/gecko-dev/master/dom/webidl/FontFace.webidl) use UTF8String. An escape operation cannot establish another operation's conversion rules. A proposed CSS preprocessing expansion also failed native serialization parity for malformed UTF16 and was rejected; its source and observations are retained with the component evidence.

Decoded CSS resource URLs are canonicalized before the resource mapper: lone surrogates and NUL become replacement characters. Focused Chromium and Firefox controls compare native computed URLs for raw and escaped inputs, valid surrogate pairs, data/blob URLs and percent escapes. Declared CSS serialization is allowed to differ between browsers. Unquoted raw NUL remains a known css-tree grammar incompatibility: native CSS accepts it, while the rewriter rejects the value and returns empty CSS. These observations support the selected URL normalization; equivalence of every css-tree grammar path with the browser remains a separate correspondence obligation.

Operation matching uses captured native functions and setters. Supported CSS attributes are selected using CSSOM's attribute-name conversion and native `CSS.supports`. Firefox exposes these as prototype setters. Chromium exposes the same family through legacy own data properties: setup records supported names from a fresh trusted declaration; each write checks the native declaration brand and current data-descriptor shape. Unknown accessors and expandos receive their original values. Ordinary own data shadows remain ordinary where the browser supports them.

The focused browser fixture compares native and mediated coercion traces, errors and declarations. It also exercises the actual `BrowserEnvironment` and QuickJS bridge with URLs absent from the installed resource catalog. A temporary build removes the actual setter mapping; the independent mapped-URL assertion must then fail. Media and image loads are blocked by fixture CSP. This checks conversion and resource mapping without an external receiver.

`FontFace` construction uses the captured native constructor identity. String-like sources are wrapped at the source argument's native conversion point; family and descriptor conversion remain native and ordered. Genuine ArrayBuffer, SharedArrayBuffer and array-buffer views remain unchanged, including detached, resizable and shared-backed values. Captured internal-slot getters identify buffers without consulting their properties. The native constructor decides which binary values it accepts. Native controls reject bare SharedArrayBuffer in the tested browsers; wrapping it as a string would incorrectly bypass that rejection.

The FontFace fixture runs the helper in Window and Worker realms, including workers without a CSS namespace. It compares native conversion traces, binary validation and proxy-of-buffer string conversion. The actual QuickJS bridge checks primitive and object sources against the resource mapper; a temporary omission of constructor mapping must fail that assertion. Worker catalogs and initialization packets are unchanged.

These adapters repair pre-effect string mapping for existing routes. Their callable selection still depends on the surrounding browser authorization boundary; this component does not establish complete DOM or CSS confinement.

Sources: pinned `@webref/idl` CSSOM and HTML interfaces; [CSS Syntax input filtering](https://drafts.csswg.org/css-syntax/#input-preprocessing), [CSS attribute declarations](https://drafts.csswg.org/cssom/#the-cssstyledeclaration-interface), [FontFace construction](https://drafts.csswg.org/css-font-loading/#dom-fontface-fontface), and [Web IDL string conversion](https://webidl.spec.whatwg.org/#es-DOMString).
